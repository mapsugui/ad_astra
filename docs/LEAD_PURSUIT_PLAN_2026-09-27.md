## Immediate correction: TOI-6695.01

The dossier's S34 reference at BJD_TDB 2459249.5428 and S61 event at 2459973.5382 match the published transit sequence of confirmed TOI-6695 b. The NASA Exoplanet Archive gives a reference mid-time of 2459249.547139 BJD and period about 80.389 d. Eberhardt et al. (2025) analyzed S34 and S61 and report transit-timing variations; Eberhardt's thesis labels these events t10 = 2459249.55 and t19 = 2459973.53. The 723.995 d spacing is nine observed orbits with timing variation, so the dossier's 26 aliases are not a new-companion period search.

The published S34/S61 event identity is documented in [the rejection note](../campaigns/toi-6695-01/REJECTION.md), with timing, source queries and the separate S88 pointing/difference-image rejection. The original generated analysis remains historical; the sky record now records a pipeline check, the local candidate was retired with its prior-art rows preserved, and the candidate collection now has three active items after the separate TOI-7610 rejection. Individual published timing uncertainties beyond the rounded thesis figure remain to be extracted before any precision TTV claim.

## Work packages and decision gates

1. **Prior art first.** For every exact TIC/TOI/Gaia identity, query current TOI and confirmed-planet ephemerides, ExoFOP, SIMBAD/VSX, ADS and the primary literature. Store UTC query date, release, row ID, period and mid-time with uncertainty, coordinate epoch and match radius. Match each event in time, not just the host within 30 arcsec. Close any other published self-match before follow-up.
2. **Archive screen and independent reductions.** Treat the four legacy campaign specs and their products as frozen baselines, including the now-retired TOI-7610 record; create a separately named follow-up campaign from refreshed source values as described above, preserving old ledger IDs and checksums. Screen MAST product/sector metadata and sizes before downloads. Use only useful light curves, TPFs and cutouts; compare SPOC SAP/PDCSAP with a suitable independent extraction or high-level product where available. A second reduction of the same pixels tests reduction dependence, not independent sky evidence. For every event vary aperture, background, PRF, quality mask and detrending; save pixel residuals and an explicit null test.
3. **Joint period and competing-model fit.** Refit mid-times and uncertainties, all allowed aliases, actual cadence/gap coverage, eccentricity, impact parameter, uncertain stellar properties, activity and possible TTV. Apply blocked time-correlated nulls and injections across the actual targets, widths and sectors. Report detection efficiency and search-wide false alarms rather than nominal sigma alone.
4. **RV and observing schedule.** Re-probe documented public RV archives, including ESO if reachable. A catalog value or a single spectrum is context; design multiple epochs to separate all allowed stellar/planet solutions, with instrumental zero-points and jitter. Compute alias-specific future BJD_TDB windows with uncertainty, use NASA TESS-point for target-specific coverage, then convert to site-specific UTC/visibility. Do not quote an old single-epoch “next transit” as current. Telescope requests, outreach and external submissions require the user's specific authorization.
5. **Disposition.** Reject or reconcile when published ephemeris, artifact, off-target source or a demonstrably sensitive predicted null explains a lead. Keep unverified whenever a key localization, period, catalog, blend or mass check is failed/inconclusive/not tested. Promote to vetted candidate only after reproducible signal, credible on-target source, calibrated search-wide statistics and a documented alternatives audit. Independently supported candidate requires an independent epoch/instrument or physical measurement consistent with that model; a second reduction of the same TESS pixels does not suffice.

Each completed test updates REPORT.md, SEARCH_LOG.md, sky_record.json, vetting artifacts and generated dossier/ledger/collection through the standard workflow, with failed and untested states preserved. Run python -m pytest -q before committing. Run python -m cygnus.publish check and inspect generated pages before any site update. Keep source products separate from derived outputs, and stage only owned paths.
